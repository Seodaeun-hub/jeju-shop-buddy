# 가게짝꿍 · 제주 소상공인 매출 대응 AI Agent

## API 연동 로컬 실행

1. 빈 개발용 PostgreSQL 데이터베이스에 `schema.sql`, `migration-store-reviews.sql`, `seed-jeju-areas.sql`, `seed-aewol-demo.sql` 순서로 적용합니다. 마지막 파일은 가상 매장과 개발용 로그인 정보를 제공합니다.
2. 백엔드에 `SHOP_BUDDY_DB_URL`, `SHOP_BUDDY_DB_USER`, `SHOP_BUDDY_DB_PASSWORD`를 설정하고 Java 21에서 `mvn -f backend/pom.xml spring-boot:run`을 실행합니다.
3. 저장소 루트에서 `npm --prefix frontend ci`와 `npm --prefix frontend run dev`를 실행합니다. 프론트엔드 개발 서버는 `/api` 요청을 로컬 백엔드의 8080 포트로 전달합니다.

기존 개발용 DB에는 `migration-store-reviews.sql`을 다시 적용해 리뷰 분류 열을 추가합니다.
기존 개발용 DB에서 AI 추천을 실행 계획에 저장하려면 `migration-strategy-recommendations.sql`도 적용합니다.
실행 가이드 저장에는 위 파일 적용 후 `migration-execution-guide-snapshots.sql`을 적용합니다.
기존 개발용 DB에서 차트 질문 대화를 저장하려면 `migration-chart-questions.sql`을 적용합니다.
기존 개발용 DB에서 POS 품목별 판매량을 저장하려면 `migration-pos-product-sales.sql`을 적용합니다.
기존 개발용 DB에서 발주 검토표를 저장하려면 `migration-inventory-review.sql`을 적용합니다.

3번 대응 전략 화면에 AI 추천을 표시하려면 [Python Agent](agent/README.md)를 먼저 실행하고, Spring Boot 실행 셸에서 `STRATEGY_AGENT_URL=http://127.0.0.1:8001`을 설정합니다. Agent 연결이 꺼져 있거나 응답을 사용할 수 없으면 같은 화면에 기본 추천을 표시합니다.

2번 매출 분석의 차트 질문도 같은 Agent를 사용합니다. 저장된 분석에서 질문하면 해당 분석의 대화를 PostgreSQL에 저장합니다. 새로고침하면 질문과 답변 당시의 근거가 복원됩니다. 공식 가이드가 필요하면 대응 전략 카드에서 가이드를 먼저 열어 두세요.
AI 추천으로 계획을 만들면 추천 이유, 매출·상권 근거와 제주 BSI가 선택 당시 값으로 저장되며, 4번 실행 관리 화면에서 다시 확인할 수 있습니다.

서버에 `REVIEW_AI_API_KEY`를 설정하면 새 리뷰 본문을 OpenAI에 보내 오후 주문 안내, 주차, 대기시간 불편을 분류합니다. `REVIEW_AI_MODEL`로 모델을 바꿀 수 있습니다. 키가 없거나 분류 요청이 실패하면 서버의 주제별 규칙을 사용합니다. 이전에 저장한 리뷰에도 규칙을 적용합니다.

## 전체 흐름 검증

개발용 계정으로 로그인하고 새 매장을 등록합니다. 월별 매출과 시간대별 결제 건수를 입력하면 분석 화면에서 저장한 값을 조회할 수 있습니다. 대응 전략의 추천 근거를 확인한 뒤 실행 계획을 생성하고 점검표 항목 하나를 완료합니다. 실행 전후 합계와 영업일 수를 입력해 결과를 저장하고, 새로고침 후 다시 로그인하여 완료 상태와 결과를 확인합니다.

애월 테스트 매장으로 위 흐름을 검증했습니다. 오후 2~5시 결제 건수 180건 → 90건을 근거로 주문 안내 점검이 추천됐습니다. 실행 결과 화면에는 하루 평균 매출 10만 원 → 15만 원(+50.00%), 하루 평균 결제 6건 → 8건(+33.33%)이 표시됐습니다. 매장부터 실행 결과까지 같은 식별자로 연결된 레코드를 PostgreSQL에서 확인했습니다.

### 애월 토스포스 엑셀 통합 테스트

2026년 11월 10일, `main`의 `92f3e13`에서 새 애월 테스트 매장을 등록하고 브라우저로 1~5번 전체 흐름을 검증했습니다.

1. **매장 등록·매출 입력** — 애월 가상 한식당의 2021년 4~5월 토스포스 엑셀을 업로드했습니다. `결제` 시트의 완료 건에서 4월 32,379,500원과 5월 29,581,000원이 집계됐습니다.
2. **매출 분석** — 매장 매출 −8.64%, 애월읍 한식 음식점업 카드 이용액 +7.34%, 제주 전체 소상공인 체감 BSI 63.1 → 64.4, 오후 2~5시 결제 337건 → 189건이 차트에 표시됐습니다.
3. **AI 추천과 계획 저장** — LangGraph가 OpenAI를 실제로 호출해 **주문 안내 점검하기**를 추천했습니다. 추천 이유와 근거, 실행 가이드의 단계와 적용 조건, 네이버 공식 링크 두 건이 실행 계획에 함께 저장됐습니다.
4. **실행 관리** — 3번 화면에서 본 가이드와 링크가 같은 순서로 표시됐습니다. 점검표 첫 항목을 완료하자 **1 / 4 완료**로 바뀌었습니다.
5. **실행 결과** — 검증용 합계와 영업일 수를 입력했습니다. 하루 평균 매출 **10만 원 → 15만 원(+50.00%)**, 결제 **6건 → 8건(+33.33%)**이 계산되고 저장됐습니다. 이 수치는 계산과 저장을 확인하기 위한 가상 값입니다.

새로고침 후 다시 로그인해 4번 화면의 실행 가이드, 공식 링크, 점검표 완료 상태와 5번 화면의 실행 결과가 그대로 표시되는 것을 확인했습니다. PostgreSQL에서 추천과 가이드 원본이 계획 저장본과 일치하고, 매장·분석·계획·점검표·결과가 연결된 것을 대조했습니다.

같은 열을 갖춘 결제 내역 CSV도 업로드, 집계, 저장을 확인했습니다. 카드 이용액은 같은 읍·면·동과 업종의 월별 합계이며, BSI는 제주 전체 지표입니다. [제주데이터허브 상권 데이터](https://data.edmgr.kr/dataView.do?id=jejudatahub-net-748) · [소상공인시장진흥공단 BSI 데이터](https://www.data.go.kr/data/3060077/fileData.do)

### 애월 LangGraph 전략 추천 검증

- **토스포스 엑셀 업로드** — 애월 가상 한식당의 2021년 4~5월 자료를 올리고 3번 대응 전략 화면을 확인했습니다. 실제 OpenAI 호출을 거친 AI 추천은 매장 매출 8.64% 감소, 같은 읍·업종의 카드 이용액 7.34% 증가, 오후 2~5시 결제 337건 → 189건을 근거로 주문 안내 점검을 제안했습니다. 제주 전체 체감 BSI 63.1 → 64.4는 경기 참고로 표시됐습니다.
- **월별 매출 직접 입력** — 같은 두 달의 매출만 입력해도 매장·상권 비교를 근거로 주문 안내 점검이 추천됐습니다. 특정 감소 시간대는 표시하지 않았고, 시간대 한정 혜택을 검토하려면 시간대별 자료, 원가와 예산을 추가하도록 안내했습니다.
- **Agent 종료 시 기본 추천** — LangGraph 서버를 종료한 뒤 같은 두 분석을 다시 열었습니다. 두 화면 모두 **기본 추천**으로 표시됐고 기존 규칙의 추천 이유와 근거를 확인할 수 있었습니다.
- **AI 추천을 실행 계획에 저장** — 애월 POS 사례에서 AI 추천을 받은 뒤 Agent를 종료하고 계획을 만들었습니다. 4번 실행 관리 화면에서 선택한 이유, 매출·상권·시간대 근거와 제주 BSI가 그대로 표시됐으며, 새로고침 후 다시 로그인해도 유지됐습니다. PostgreSQL에서 추천 원본과 계획에 저장된 내용이 일치하고, 다른 분석의 추천 ID로 계획을 만들면 409가 반환되는 것을 확인했습니다.

### 애월 실행 가이드 화면 검증

3번 대응 전략 화면의 **주문 안내 점검하기** 카드에서 **어떻게 실행하나요?**를 눌렀습니다. Spring Boot가 Python LangGraph의 실행 가이드 API를 호출하고, 카드 안에 실행 단계와 단계별 공식 출처를 표시합니다.

- **애월 POS 업로드** — 가상 한식당의 2021년 4~5월 POS 분석에서 오후 2~5시 실제 주문 가능 시간을 먼저 점검하도록 안내했습니다. 네이버 영업시간과 예약·주문 도움말 링크가 각각 표시됐고, 예약·주문 단계에는 해당 서비스를 이용하는 경우라는 조건이 붙었습니다.
- **월별 매출 직접 입력** — 같은 두 달의 월별 매출만 있는 분석에서는 매장 전체의 주문 가능 시간과 휴게시간을 점검하도록 안내했습니다. 특정 시간대를 표시하지 않았고, 네이버 영업시간 도움말 링크를 확인했습니다.
- **관련 문서 없음** — 애월 POS 분석에서 채널을 **매장 안내**로 바꾸자 관련 공식 가이드가 없다는 메시지와 매장 입구 안내를 대조하는 단계가 표시됐습니다. 응답 상태는 `NO_RELEVANT_GUIDE`였고, 출처 목록은 비어 있었습니다.

브라우저에서 버튼을 처음 열 때 가이드를 요청하고, 같은 카드와 채널을 다시 열면 받은 결과를 재사용하는 것도 확인했습니다. 네이버 안내 두 사례는 실제 OpenAI 호출로 검증했습니다.

### 애월 실행 가이드 저장 검증

애월 가상 한식당의 POS 분석에서 3번 **주문 안내 점검하기** 카드의 네이버 가이드를 열었습니다. Agent를 종료한 상태에서 계획을 저장하고, 4번 **실행 관리** 화면에서 오후 2~5시 주문 가능 여부를 확인하는 단계, 예약·주문 단계의 적용 조건, 네이버 공식 링크 두 건이 3번 화면과 같은 순서와 내용으로 표시되는 것을 확인했습니다.

브라우저를 새로고침하고 다시 로그인한 뒤에도 같은 단계와 링크가 표시됐습니다. PostgreSQL에서 조회 당시의 가이드와 계획에 저장된 가이드가 일치했고, 같은 가이드를 다른 전략의 계획에 연결하려는 요청은 `409`로 거부됐습니다.

### 애월 리뷰 개선 계획 테스트

1. 애월 가상 한식당의 매출 분석 화면에서 가상 리뷰 3건을 날짜와 함께 등록했습니다. 긍정적인 주문 안내 리뷰 1건과 오후 주문 안내가 헷갈렸다는 리뷰 2건을 사용했습니다.
2. 같은 불편을 언급한 두 번째 리뷰가 저장되자 대시보드에 **3건 중 2건**이 표시됐습니다. 근거를 펼치면 해당 리뷰 2건의 날짜와 원문을 확인할 수 있었습니다. 이 테스트에서는 오후 식사 주문 안내를 확인했습니다.
3. **오후 2~5시에도 식사 주문을 받아요**를 확인하고 **안내 개선 계획 만들기**를 선택했습니다. PostgreSQL에 **오후 식사 주문 안내 개선** 계획과 점검표 4개, 근거 리뷰 2건이 저장됐습니다. 새로고침 후 다시 로그인해도 대시보드의 리뷰 집계와 실행 계획의 리뷰 근거를 다시 조회할 수 있었습니다.

### 애월 주차·대기시간 리뷰 테스트

애월 가상 한식당에 주차 불편 2건, 대기시간 불편 2건, 두 불편이 없었다는 리뷰 1건을 추가했습니다. 대시보드는 주차와 대기시간을 각각 **근거 리뷰 2건**으로 묶었고, 각 카드에서 날짜와 원문을 확인할 수 있었습니다.

- **주차 안내 개선** 계획에는 이용 가능한 주차장과 입구를 확인하고 매장 안내와 지도에 반영하는 점검표가 저장됐습니다.
- **대기시간 안내 개선** 계획에는 실제 대기시간을 기록하고 입구에서 예상 대기시간을 안내하는 점검표가 저장됐습니다.

두 계획 모두 PostgreSQL에 주제와 근거 리뷰가 저장됐고, 저장된 계획을 다시 조회해 동일한 근거를 확인했습니다.

앞의 테스트는 API 키 없이 서버의 규칙 기반 분류로 진행했습니다.

#### 실제 OpenAI 호출 검증

애월 가상 한식당에 새 테스트 리뷰 5건을 등록했습니다. OpenAI 응답으로만 채워지는 PostgreSQL의 `model_topics`를 확인한 결과, 주차 불편 2건은 `PARKING`, 대기시간 불편 2건은 `WAIT_TIME`으로 저장됐습니다. 긍정 리뷰 1건은 불편 주제 없이 저장됐습니다.

대시보드에서 새 리뷰가 각 주제의 근거로 표시되는 것을 확인했습니다. **주차 안내 개선**과 **대기시간 안내 개선** 계획을 각각 저장하고 다시 조회해, 주제별 새 근거 리뷰와 점검표 4개가 각 계획에 포함된 것을 확인했습니다.

### PR #7 머지 후 애월 POS 1~5번 브라우저 재검증

`main`의 `012267e`에서 새 애월 가상 한식당을 등록하고, 실제 OpenAI와 로컬 PostgreSQL에 연결한 상태로 전체 흐름을 다시 확인했습니다.

1. **매장 등록·매출 입력** — 2021년 4~5월 POS 엑셀을 브라우저에서 업로드했습니다. 4월 매출 **32,379,500원**, 5월 매출 **29,581,000원**과 시간대별 결제 건수가 미리보기에 표시됐고, 분석에 저장됐습니다.
2. **매출 분석·차트 질문** — 실제 OpenAI에 **“제주 경기는 어땠고, 우리 가게는 언제 많이 줄었어요?”**라고 원문 그대로 물었습니다. **제주 BSI 63.1 → 64.4**와 **오후 2~5시 결제 337건 → 189건**만 각각의 근거와 함께 표시됐습니다. 실행 계획 안내나 추가 입력 요청은 없었고, 새로고침 후 질문과 답변이 복원됐습니다.
3. **대응 전략 선택** — 실제 AI가 추천한 **주문 안내 점검하기**를 선택했습니다. 추천 이유와 실행 단계, 네이버 공식 도움말 링크 **2건**이 실행 계획에 저장됐습니다.
4. **실행 관리** — 점검표 **4개 중 1개**를 완료했습니다. 새로고침 후에도 완료 상태와 저장한 가이드 링크가 유지됐습니다.
5. **실행 결과 확인** — 가상 실행 결과를 입력해 하루 평균 매출 **100,000원 → 150,000원(+50.00%)**, 결제 **6건 → 8건(+33.33%)**을 확인했습니다. 새로고침 뒤에도 같은 결과가 표시됐고, 대시보드의 기존 대화에서 실행 결과를 이어 물었을 때도 저장 값이 그대로 반환됐습니다.

PostgreSQL에서 같은 분석에 질문 **3턴**, 완료한 점검 항목 **1개**, 공식 가이드 링크 **2건**, 실행 결과 **1건**이 연결된 것을 확인했습니다.
