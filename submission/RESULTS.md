# 결과 설명자료

## 문제와 구현 목표

제주 소상공인이 매출 감소를 봐도 상권의 흐름인지, 특정 메뉴·시간대 문제인지 파악하고 실행으로 옮기는 데 여러 자료와 도구가 필요합니다. 가게짝꿍은 필수 제주 데이터를 매장 POS와 같은 지역·업종·기간으로 연결하고, 근거에서 발주·홍보 준비와 후속 기록까지 이어줍니다.

## Agent 구조와 Workflow

사용자 CSV·매장 설정 → 브라우저 파일 검사/집계 → Spring API의 소유권 확인·저장·사실/출처 구성 → Python LangGraph/도구·공식 가이드 검색·외부 모델 → 구조화 응답/근거 검증 → 사장님 확인 → 실행 계획/초안·공개 메뉴판 저장 → 실행 결과 재조회입니다.

개인 참가자가 기획·데이터 정리·개발·테스트·촬영/문서 준비를 담당합니다. AI 도구 활용 범위는 AI_AND_OSS에 구분했습니다. Agent는 분석 요약·질문·후보 전략·후기 포인트·홍보 초안·번역을 지원합니다. 발주 확정·홍보 검토·실제 게시·QR 공개는 사용자가 결정합니다.

## 검증 방법과 실제 확인 범위

- CSV 생성 가정과 예상 JSON을 분리하고 `validate_demo.py`와 `validate_follow_up.py`로 결제/상품 금액·일별 수량·재료 수지를 확인합니다. 묶음을 만든 시점의 실행 결과는 `package-validation.json`에 기록합니다.
- 기존 프런트엔드 홈·개별 기능 테스트 기록은 소스 README와 시연 verification.md에 있습니다. 과거 자매국수 검증을 더애월 새 자료의 검증으로 바꿔 쓰지 않습니다.
- 2026-11-18 새 도메인에서 실제 계정 로그인·저장 분석·AI 질문 응답·공개 메뉴판을 확인했습니다. 인증 없는 공개 API는 HTTP200, 메뉴5·사진5입니다. 브라우저 네 언어 전환·김치찌개8,000원과390×844 화면에서 가로 넘침 없음을 확인했습니다. 캡처는 이 관찰에 해당합니다.
- 사용자는 더애월 분석의 메뉴·시간대 수치, 발주20~24·0.5~0.9kg, 세 채널 초안과 가상 실행 결과 저장을 확인했습니다. 내일 새 주소의 실제 아이폰 촬영·재검증은 별도 예정입니다.

## 한계와 센터 활용

실제 매장 운영 참여·실제 매출 개선·외부 주문·광고 인과 효과는 검증하지 않았습니다. POS·레시피·재고·후속 결과는 가상입니다. 날씨는 사후 과거 관측이며 실제 입수 시점을 재현한 예측 성능 실험이 아닙니다. 정적 공공자료의 최신성, 외부 API 이용조건·쿼터·비용, 공개 후기 확인, 번역·홍보 표현의 사용자 검토가 필요합니다.

센터에서는 인터넷이 가능한 PC에 Web·DB·Agent를 설치하고 데이터 활용 교육·소상공인 상담의 보조 도구로 사용할 수 있습니다. 평가용 AI 계정과 외부 API 설정이 필요하며 로컬 GPU 추론은 요구하지 않습니다. 센터 지정 PC에서 실제 새 설치·부하·장기 운영을 검증했다고 주장하지 않습니다. 향후 최신 공공자료 갱신 파이프라인과 실제 매장 동의 기반 검증을 별도 과제로 둡니다.
