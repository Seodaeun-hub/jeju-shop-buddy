# 제출 준비 안내

참가 방식: **개인 참가**. 사용자 확인으로 팀 관련 정리는 완료됐습니다. 2026-11-18 기준 작성본이며 업로드·최종 제출 자체는 수행하지 않았습니다.

기획서는 **문제/목표 → 제주 필수 데이터와 활용 → 핵심 사용자 흐름 → Agent 역할·판단·자율 범위 → 모델·Tool·RAG → UI와 실행 결과 → 검증·한계 → 센터 탑재 환경·외부 의존성 → 활용 효과·향후 계획** 순서로 12~15쪽 안에 구성합니다. 기획서는 별도 필수 제출물이며 Markdown 설명서가 최종 기획서 파일을 대신하지 않습니다.

## ZIP 구성

단계별 CSV와 사진 5장·가격·원가표·새 QR의 위치, 실제·가상 자료 구분과 검증 내역은 [포함 자료 기록](PACKAGE_CONTENTS.md)에 정리했습니다. 사진·생성 프롬프트·새 QR·검증 캡처 원본은 `submission/assets/`에 포함하므로 이 브랜치를 받은 다른 PC에서도 기본 입력 자료를 사용할 수 있습니다.

`01_실행소스`는 실행 코드·모델 프롬프트·SQL·검증 코드를 포함합니다. `02_문서`는 실행·데이터·AI/오픈소스·결과 설명입니다. `03_촬영자료`는 CSV·사진·입력표·새 QR을 번호별로 나눈 묶음입니다. `04_검증캡처`는 이번 작업에서 실제 관찰한 화면이며, 내일의 녹화나 실제 매장 검증을 뜻하지 않습니다. 파일별 경로·크기·SHA-256은 `manifest.json`, 자료 출처·구분은 DATA_SPEC과 포함 자료 기록에 정리합니다.

압축에는 `.git`, `.env`, 가상환경, node_modules, 빌드 캐시, 실제 DB 덤프·세션·로그인 비밀번호·API 키를 넣지 않습니다. 예시 변수만 제공합니다. 공식 규칙상 외부 AI 평가용 키를 심사위원용 ZIP에 별도 포함할 수 있지만, 공개 소스·기획서·영상에는 넣지 않습니다. 평가용 키는 참가자가 비용·한도를 관리하고 평가 후 폐기합니다. 데이터 API 키는 발급·설정 방법만 안내합니다.

검토본은 **실제 키 누락을 포함해 정상 실행에 필요한 외부 설정을 심사자에게 별도 전달할 방법을 확정한 뒤** 제출합니다. 이미 설정된 개인 운영 키를 그대로 추출하거나 복사하지 않습니다.

재생성은 소스 루트에서 `python submission/build_package.py --output 새_출력폴더`를 실행합니다. 기본값은 이 브랜치의 `submission/assets/menu` 사진·프롬프트와 `submission/assets/verification` QR·캡처를 사용합니다. 다른 입력은 `--menu-assets 사진폴더 --verified-assets QR과캡처폴더`로 지정합니다. 기존 출력 폴더를 지우거나 덮어쓰지 않습니다. 폴더별 manifest의 크기·SHA-256과 ZIP CRC를 검사하며, 알려진 키 패턴·개인 키 파일·개발 캐시를 제외합니다. 자동 검사가 모든 민감정보를 식별한다는 보장은 아니므로 제출 전 최종 검토가 필요합니다.

## 제출 직전

1. 별도 기획서 파일 15쪽 이내, 최종 영상 링크 접근 가능 여부를 확인합니다.
2. ZIP을 경로가 짧은 빈 폴더(예: `C:\gage-demo`)에 풀어 소스·문서·CSV·사진·새 QR과 manifest를 확인합니다.
3. RUNBOOK의 설치·키·DB 절차를 점검합니다. 새 PC의 설치·센터 최소사양 실행은 아직 검증하지 않았습니다.
4. 사용한 이미지·외부 코드의 출처와 사용권 고지를 최종 확인합니다. 이번 정리에서 모든 기존 자산의 권리 감사를 마쳤다는 뜻은 아닙니다.
5. 공식 대회 **갤러리 → 기획서 및 최종 결과물 제출**에서 두 필수 파일을 올리고 최종 제출 상태를 확인합니다. 이 안내 작성만으로 제출 완료가 되지 않습니다.
