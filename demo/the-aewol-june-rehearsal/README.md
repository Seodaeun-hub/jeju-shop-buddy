## 1. 시연 기준일과 매장 선택

1. 로그인하고 왼쪽 사이드바의 **시연 기준일**을 펼칩니다. 모바일은 **메뉴 열기** 안에 있습니다.
2. **날짜 변경 또는 시연 기준일 설정 → 애월 시연 · 2021년 6월 1일 → 시연 날짜 적용**을 누릅니다. `2021.06.01` 표시를 확인하고 접습니다.
3. **내 매장 → 매장 선택 → 더애월 본점**을 고릅니다. 이전 검증에서 이 상호의 매장을 등록했다면 재사용합니다. 아직 없으면 **새 매장 등록**을 누릅니다.

| 입력 | 값 |
|---|---|
| 가게 이름 | **더애월 본점** — 후기 검색이 상호를 확인하므로 뒤에 ‘시연점’ 등을 붙이지 않음 |
| 주소 | **제주특별자치도 제주시 애월읍 하가로 159** |
| 상세주소·메모를 적을 수 있는 칸 | `공개 정보 참고 · 매출·재고·원가는 가상 시연` |
| 읍·면·동 | **제주시 애월읍** |
| 업종 | **한식 음식점업**에 해당하는 한식 업종 |

PC·서버 날짜는 바꾸지 않습니다. 이 계정의 시연 기준일만 적용하며 로그인·저장 시각은 실제 날짜입니다. 일반 사용은 **날짜 변경 → 실제 날짜로 돌아가기**로 복귀합니다.

## 2. 새 POS 네 개 저장

**내 매장 → POS 파일 관리 → 달력 보기 → 4월 30일 또는 5월 31일 → 파일 추가** 순서로 네 파일을 각각 저장합니다.

- 파일 종류를 **결제 내역**과 **상품 주문**으로 정확히 나눕니다.
- 내보내기 시작·종료일은 위 표대로 입력하거나 비워 두고 다음 단계에서 월 전체 여부를 확인합니다.
- 달력 기록일은 보관용 날짜이며, 매출 집계는 CSV 안의 거래일을 사용합니다.
- 이미 이번 네 파일이 있으면 중복 업로드하지 않습니다. 다른 월·다른 시연 파일을 동시에 선택하지 않습니다.
- 이번 과거 시연에는 현재 토스 테스트 가맹점의 11월 주문을 불러오지 않습니다.

## 3. 새 분석 만들기와 ‘요즘 고민’ 입력

**매출 입력 → 더애월 본점 → POS 파일 업로드 → 내 매장 월별 파일**로 이동합니다.

1. 기준 월 **2021-04**, 비교 월 **2021-05**를 선택합니다.
2. 각 월의 `SIMULATED-` 결제·상품 주문 파일을 고릅니다.
3. 네 파일의 **월 전체 여부 확인**에서 **이 파일은 … 전체 내역이에요. (휴무·무거래일 포함)**을 체크합니다. 이 CSV는 각 월 전체를 내보낸 가상 자료이며 일요일을 무거래일로 설정했습니다. 실제 식당의 영업일을 관측한 자료는 아닙니다.
4. **보관한 POS 집계 완료**, 두 달 매출, **상품 주문 5개 품목**을 확인합니다.
5. 분석 이름은 **더애월 공개정보 참고 · 2021년 6월 가상 운영 시연**으로 적습니다. 이전 ‘공개 후기 연동 검증 · 가상 매출’ 분석과 구분합니다.

**요즘 어떤 점이 고민인가요?**에 다음 문장을 넣습니다.

> 4월보다 5월 매출이 줄었어요. 같은 애월 한식 상권과 비교해 우리 가게 상황을 알고 싶어요.
> 매출이 가장 많이 줄어든 메뉴와 결제가 줄어든 시간대를 찾아주세요.
> 그 근거로 6월 발주량을 검토하고, 실제 공개 후기에서 확인한 메뉴 특징을 살려 홍보하고 싶어요.

**이 자료로 분석하기**를 누릅니다. 메뉴 이름이나 감소 수치를 고민에 미리 넣지 않습니다.

당시 공개 글의 가격을 참고한 5개 품목입니다. **가격은 실제 자료에서 가져왔고 판매량은 가상**입니다. POS·사진·재료·QR에는 아래 ‘앱 메뉴명’을 동일하게 사용합니다.

[2021-02-14 글](https://fantasticade.tistory.com/386)에 가격이 기재돼 있습니다. [2021-05-30 두루치기 방문 글](https://chrkdfur76.tistory.com/entry/제주-맛집-두루치기-더-애월)도 두루치기·밥 별도 구성을 확인하는 참고 자료입니다. 기존의 고기국수·만두·감자전·전복비빔밥 등은 더애월의 확인된 메뉴로 사용하지 않습니다. 계란말이는 판매 사실만 확인돼 당시 가격을 임의로 만들지 않았습니다.

**내 매장 → 메뉴 사진 관리**에서 이번 5개 품목을 확인합니다. 김치찌개는 [AI 예시 사진](images/kimchi-stew-ai-illustration.png)을 사용할 수 있습니다. 이는 실제 더애월 사진이 아니며 찰솥밥 포함 전체 상차림을 재현한 것도 아닙니다. 나머지 4개는 사용할 권한이 있는 해당 메뉴 사진이 준비됐을 때만 등록합니다. 돔베고기 사진을 두루치기 사진으로 바꿔 붙이지 않습니다. 사진이 없는 메뉴도 이름·가격으로 QR에 표시할 수 있습니다.

**내 매장 → 메뉴 재료·원가 → 김치찌개**에서 [재료·원가 입력표](menu-ingredients.md)를 입력합니다. 김치찌개는 **8개 재료·합산 3,100원**입니다. 다른 4개 메뉴의 입력표도 같은 문서에 있습니다. 해당 식당의 실제 레시피·매입가가 아니라 계산을 보여주기 위한 가정입니다. 입력 후 **재료·원가 저장**을 누르고 새로고침해 확인합니다.

## 6. 제주 데이터가 반영된 AI 전략

같은 분석의 **대응 전략 보기 → 근거와 출처 보기**에서 **가상 매출 감소**, **오후 결제 감소**, **제주데이터허브 상권 카드 이용액 증가**를 확인합니다. 필수 데이터는 그래프 장식이 아니라 상권과 매장의 흐름을 구분하는 분석·전략 근거로 사용합니다.

AI 문장은 매번 달라질 수 있습니다. 수치·단위·출처와 제안 행동이 연결되는지 확인합니다. 처음에는 주문 안내 점검을 제안할 수도 있으므로 실제로 수행하지 않은 일은 완료 체크하지 않습니다. 발주와 홍보는 아래 카드에서 이어갑니다.

| 앞 3회 → 최근 3회 평균 | **30 → 22인분**, **−26.67%** |
| 최근 수준을 사용한 범위 | **20~24인분**. 월 감소율을 다시 곱하지 않음 |
| 과거 날씨 | 제주 관측소의 실제 관측. 강수·비강수 각각 3회 조건이 부족하면 날씨 보정을 생략하고 이유를 표시 |

이 범위는 CSV와 현재 계산 규칙으로 재현할 **수요 시나리오**이며 통계적 신뢰구간·실제 판매 예측 정확도 검증이 아닙니다. 6월 5일 강수 관측은 사후 관측으로 조건을 재구성한 것으로, 당시 예보가 아닙니다. 실제 자료 공개·입수 시점까지 재현한 백테스트라고 설명하지 않습니다.

자동으로 불러온 8개 재료에서 **현재 재고와 기존 입고 예정량**을 [입력표](menu-ingredients.md#김치찌개-발주-입력값)대로 적습니다. 돼지고기는 다음처럼 확인합니다.

| 항목 | 값 |
|---|---|
| 한 인분 사용량 | 돼지고기 원육 **0.1kg** |
| 현재 재고 / 기존 입고 | **1kg / 0.5kg** |
| 예상 사용량 | **2~2.4kg** |
| 추가 준비량 | **0.5~0.9kg** |
| 최종 추가 발주량 예시 | **1kg**. 사장님이 포장 단위를 고려해 선택 |

나머지 재료도 입력하고 **발주 검토표 저장**을 누릅니다. 기존 입고는 이미 주문해 해당 날짜에 사용할 물량입니다. 이번 추가 발주량을 입고 칸에 넣지 않습니다. 상단 **실행 결과 확인 →**에서 저장한 수량을 확인하고, 실행 후 남은 재고는 아직 입력하지 않습니다. 실제 주문은 전송되지 않습니다. 다른 메뉴의 공동 재료 사용량까지 자동 합산한 매장 전체 발주 최적화라고 설명하지 않습니다.

## 8. 할인 검토와 실제 후기 선택

같은 분석의 **대응 전략 → 시간대 한정 혜택 검토 → 선택하기**에서 **시작일 2021-06-01·2주·인스타그램·예산 30,000원**으로 계획을 만듭니다. **프로모션 검토**에 아래 값을 넣습니다.

| 입력·결과 | 값 |
|---|---:|
| 메뉴 / 정상가 | 김치찌개 / **8,000원** |
| 저장한 합산 원가 | **3,100원** |
| 개당 할인 / 예산 | **1,000원 / 30,000원** |
| 할인 후 가격 / 최대 수량 | **7,000원 / 30개** |
| 할인 후 재료비 차감액 | **3,900원**. 인건비·임대료 등이 빠지기 전이며 순이익 아님 |
| 기간 | **2021-06-01~14** |

**프로모션 검토 저장 → 홍보물 만들기 → 이 메뉴 후기 찾기**를 누릅니다. `2021-06-01 기준 최근 180일`과 **확인한 공개 후기 → 출처 보기**에서 작성일·원문을 확인합니다. 검증된 후보는 **2021-02-14** 더애월 본점 김치찌개 후기입니다. 2020-01-26 글은 오래된 참고 자료일 뿐 이 180일 검색 범위의 후기라고 설명하지 않습니다. 5월 30일 두루치기 후기를 김치찌개 시식 근거로 바꾸지 않습니다.

솥밥·누룽지 구성, 김치찌개를 먹은 경험처럼 **원문이 지지하는 포인트만 선택**합니다. 포인트 개수·문장은 AI 응답에 따라 달라집니다. 후기 검색에 실패하면 **후기 다시 찾기**를 누릅니다. 계속 실패하면 이번 실검색이 실패했다고 표시하고, 가짜 후기나 다른 식당 후기로 대체하지 않습니다. 기존 검증 계획의 저장 출처는 다시 확인할 수 있지만 이를 새로운 실검색 성공이라고 말하지 않습니다.

게시일 **2021-06-01**, 시간 **11:00**, 행사 **제주현대미술관 《공(空)의 매혹》 전시**, 김치찌개 사진을 선택한 뒤 **선택한 포인트로 세 채널 초안 만들기**를 누릅니다. 음식 사진은 해당 메뉴의 AI 예시 사진임을 설명합니다.

## 9. 세 채널 초안 검토와 아이폰 확인

**홍보물 보기**에서 인스타그램·네이버 플레이스·당근을 확인합니다. PC에서는 세 칸, 좁은 화면에서는 채널 탭으로 표시될 수 있습니다.

- 각 문구에서 선택한 후기 특징과 김치찌개 안내가 이어지는지 봅니다.
- **7,000원·30개 한정·6월 1~14일**, 후기 작성일·출처, 전시 기간·출처가 맞는지 확인합니다.
- 전시가 식당과 제휴했다거나 식당 근처에 있다는 표현을 쓰지 않습니다.
- 원문에 없는 식감·조리 방식·1인 주문 가능 여부는 **초안 수정하기**에서 정리하고 **홍보 초안 변경 저장**을 누릅니다. 새 생성에서도 표현 검토는 필요합니다.
- 이전 검증에서는 ‘육수를 오래 끓인다’는 문장을 원문에 맞는 먹는 방법으로 고치고, ‘혼자 식사해도 좋다’는 미확인 안내를 삭제했습니다. 그 수정은 생성 모델의 보장이 아니라 사장님 검토 단계입니다.
- 새로고침 후 **홍보물 보기**를 다시 열어 내용과 출처가 유지되는지 확인합니다.
- 실제 아이폰 Safari에서 같은 계획을 열어 채널 전환·하단 버튼·**문구 복사·이미지 저장**을 확인합니다. 이 새 5메뉴 시연의 실제 아이폰 재검증은 사용자가 진행할 항목입니다.

시연에서는 SNS에 실제 게시·예약하지 않습니다. 이 할인은 실제 식당에서 진행하는 행사가 아닙니다. 공개 후기 선택·초안 작성·검토·저장까지 보여줍니다.

## 끝내기 전에 확인할 것

- 새 네 CSV로 만든 분석의 매출·김치찌개 감소·오후 결제 수치가 위 표와 맞는지 확인합니다.
- 제주데이터허브 근거가 AI 전략에 연결됐는지 봅니다. 카드 이용액을 방문객이나 식당 실매출로 표현하지 않습니다.
- 발주는 선택한 하루의 검토이며 외부 주문·성과 개선을 주장하지 않습니다.
- 실제 후기에서 골라 홍보 초안을 만들었는지, 사장님이 미확인 표현을 정리했는지 구분합니다.
- 이번 새 자료의 전체 Railway·실제 아이폰 리허설은 위 순서로 다시 진행합니다. 이전 더애월 후기 검증용 소규모 매출 150만→133만 원 결과를 이 CSV 결과로 재사용하지 않습니다.
