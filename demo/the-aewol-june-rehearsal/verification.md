# 더애월 기준 새 시연 자료 검증

검증일: **2026-11-18**. 대상은 이 폴더의 새 5개 품목 CSV와 입력 참고표입니다.

## 이번에 확인한 내용

- 앱이 실제 사용하는 `frontend/src/data/pos.ts`의 **월별 결제·상품 주문 집계**로 네 CSV를 읽었습니다. 월 매출 **16,342,500원 → 14,508,000원**, 5개 품목의 정상가·판매량·실판매금액, 시간대별 결제 **312/208/260 → 312/104/260**이 예상값과 일치했습니다.
- 같은 앱의 **파일 날짜 검사**에서 각 파일 거래일 **26일**, 4월 범위 **4/1~30**, 5월 범위 **5/1~31**을 확인했습니다. 거래가 없는 일요일까지 포함한 월 전체 내보내기 설정은 시연 가정입니다.
- 같은 앱의 **보관 상품 주문 일별 읽기**로 김치찌개 토요일 수량을 확인했습니다. 6월 5일의 최근 6회는 **30·32·28·22·24·20인분**입니다.
- 별도 Python 검증으로 **모든 결제 1,456건 각각**에 대해 상품 주문 금액 합계가 해당 결제 금액과 같음을 확인했습니다. 주문 후 9분에 결제하도록 설정한 가상 기록을 사용했습니다.
- 모든 메인 메뉴 주문은 2인분 이상이고 문어사리는 두루치기 주문과 함께 들어 있습니다. 취소·부분 환불·기존 10개 메뉴·현재 토스 테스트 주문은 새 파일에 넣지 않았습니다.
- 메뉴별 재료 사용량×단가 합계는 **3,100 / 3,100 / 3,420 / 3,460 / 4,060원**입니다. 김치찌개 수요 20~24인분에 대한 8개 재료의 사용량·재고·기존 입고·부족량·최종 수량 예시를 산술 대조했습니다.
- 현재 서버에 포함된 제주데이터허브 집계와 애월읍 한식 카드 이용액 **2,049,456,994원 → 2,199,885,864원**, 증가율 **7.34%**를 대조했습니다. 가상 POS를 이 공공데이터에 덮어쓰지 않았습니다.

## 이전 확인과 구분

앞선 Railway 검증에서는 같은 상호·주소의 별도 **소규모 가상 매출 분석**에서 **2021-06-01 기준 공개 후기 검색 → 2021-02-14 원문 1개·포인트 선택 → 세 채널 초안 저장**을 확인했습니다. 최종 검토에서 두 문장을 승인받아 정리했고 출처·7,000원·30개 한정·6월 1~14일이 재조회 후 유지됐습니다.

그 결과는 공개 후기 기능의 검증이며 **이번 새 네 CSV 전체를 Railway에서 다시 시연한 결과는 아닙니다.** 원문에 없는 맛·식감·조리법·1인 주문 안내는 새 초안에서도 사장님이 확인합니다.

## 사용자와 다시 확인할 항목

새 CSV 업로드·월 전체 확인·분석 저장, 실제 AI의 메뉴·시간대 근거와 전략, 6월 5일 발주 화면의 20~24인분·기상 관측 표시, 레시피·재고 저장과 재조회, 새 계획의 후기 검색·홍보 초안, QR 공개·실제 아이폰 네 언어 전환을 [README 순서](README.md)로 다시 확인합니다.

실제 식당의 운영 참여·매출·재고·원가·레시피·광고 성과·발주 정확도는 검증하지 않았습니다. 실제 주문이나 SNS 게시를 실행하지 않습니다.

## 재현 방법

이 폴더에서 `python build_demo.py`로 자료를 다시 만들고 `python validate_demo.py`로 결제·상품 주문·원가·재고 계산을 독립 검증할 수 있습니다. 재생성 스크립트와 CSV는 동일한 가상 시나리오를 담고 있습니다. 앱 파서 대조는 실제 프런트엔드의 `importMonthlyPos`, `inspectPosDates`, `readArchivedProductDays`를 사용했습니다.
