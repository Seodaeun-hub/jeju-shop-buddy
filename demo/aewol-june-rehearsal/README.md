# 2021년 6월 애월 운영 의사결정 시연

**2021년 4·5월 매출·상권 비교 → 감소 근거 질문 → 6월 대응 전략 → 발주 검토 → 전시 연계 홍보 → 다국어 QR 메뉴판** 순서로 진행합니다. 매장은 가상이며 POS와 재료·원가도 시연 자료입니다. 제주데이터허브 카드 이용액과 기상청 과거 관측은 출처를 확인할 수 있는 자료를 사용합니다.

## 시작 전 준비

- PC에서 [Railway 가게짝꿍](https://magnificent-love-production-5f461553.up.railway.app/)을 열고 새로고침합니다. 아이폰도 같은 HTTPS 주소를 사용합니다. 같은 Wi-Fi나 로컬 포트·인증서 설치는 필요하지 않습니다.
- 시연 계정으로 로그인합니다. 계정과 비밀번호는 별도로 전달하며 이 문서에는 기록하지 않습니다.
- 아래 CSV 네 개와 메뉴 사진을 준비합니다. 사진은 사용할 권한이 있는 자료를 사용하며 생성형 AI 사진이면 기획서에 그 사실을 적습니다.
- 처음 등록하는 순서로 설명합니다. 기존 매장을 재사용할 때는 이미 저장한 파일·사진·재료는 확인하고 다음 단계로 넘어갑니다. 같은 CSV를 반복 업로드하지 않습니다. 새 매출 분석은 별도 이름으로 저장할 수 있습니다.

| 파일 | 앱의 파일 종류 | 내보내기 기간 | 달력에 기록할 날짜 예시 |
|---|---|---|---|
| [2021-04-payment.csv](2021-04-payment.csv) | 결제 내역 (엑셀·CSV) | 2021-04-01~30 | 2021-04-30 |
| [2021-04-product.csv](2021-04-product.csv) | 상품 주문 (CSV) | 2021-04-01~30 | 2021-04-30 |
| [2021-05-payment.csv](2021-05-payment.csv) | 결제 내역 (엑셀·CSV) | 2021-05-01~31 | 2021-05-31 |
| [2021-05-product.csv](2021-05-product.csv) | 상품 주문 (CSV) | 2021-05-01~31 | 2021-05-31 |

CSV는 가상 POS의 결제·상품 주문 시트를 월별로 내보낸 자료입니다. 달력에 표시할 기록일과 실제 거래 기간을 구분합니다. 매출 집계에는 파일 속 거래일과 완료 상태를 사용합니다.

## 1. 사이드바에서 시연 기준일 설정

PC 왼쪽 메뉴 아래의 접힌 **시연 기준일**을 펼칩니다. 사이드바가 접혀 있으면 **메뉴 열기**를 먼저 누릅니다. 아이폰은 왼쪽 위 **메뉴 열기**를 누른 뒤 같은 항목을 펼칩니다.

**시연 기준일 설정** 또는 **날짜 변경 → 애월 시연 · 2021년 6월 1일 → 시연 날짜 적용**을 누릅니다. 접힌 항목의 날짜가 **2021.06.01**인지 확인한 뒤 다시 접습니다. 본문 위에는 큰 날짜 배너가 표시되지 않습니다.

PC의 시스템 날짜는 바꾸지 않습니다. 같은 계정의 다른 기기는 새로고침하면 적용됩니다. 로그인·저장 시각은 실제 시간을 유지합니다.

## 2. 가상 매장 등록

**내 매장 → 새 매장 등록**을 누르고 아래 값을 입력한 뒤 **매장 등록**을 누릅니다.

| 입력 항목 | 시연 값 |
|---|---|
| 가게 이름 | 애월 가상 한식당 |
| 업종 | 한식 음식점업에 해당하는 한식 업종 |
| 주소 | 제주특별자치도 제주시 애월읍 애월해안로 7 |
| 제주 읍·면·동 | 제주시 애월읍 |

주소를 입력한 뒤 읍·면·동이 애월읍으로 연결됐는지 확인합니다. 이 주소는 관측소 매칭을 위한 시연용 주소이며 실제 식당의 운영 자료를 사용하는 것은 아닙니다. 이미 같은 가상 매장을 등록했다면 매장 선택에서 그 매장을 선택합니다.

## 3. POS CSV 네 개 저장

**내 매장 → POS 파일 관리 → 달력 보기**에서 4월 말 또는 5월 말 기록일을 선택합니다. **파일 추가**가 보이면 펼칩니다.

표의 파일마다 **파일 종류 선택 → POS 파일 선택 → 파일 저장**을 진행합니다. **내보내기 시작일·종료일은 비워도 저장할 수 있습니다.** 파일 속 거래 날짜로 4·5월 자료를 자동으로 찾으며, 월 전체 여부는 다음 단계에서 확인합니다. 알고 있는 내보내기 기간을 미리 입력해도 됩니다.

**전체 파일**에서 파일 종류와 기간을 확인합니다. 이미 네 개가 있으면 다시 올리지 않고 그대로 사용합니다. 이 과거 시연에서는 네 개 CSV를 사용하며, 현재 테스트 가맹점의 토스 주문을 섞지 않습니다.

## 4. 4·5월 분석 만들기

**매출 입력**에서 가상 매장을 선택하고 **POS 파일 업로드 → 내 매장 월별 파일**로 이동합니다.

| 입력 항목 | 시연 값 |
|---|---|
| 기준 월 | 2021-04 |
| 비교 월 | 2021-05 |
| 각 월의 파일 | 해당 월의 결제·상품 주문 파일 |
| 분석 이름 | 애월 2021년 6월 대응 시연 |

월을 고르면 해당 월 거래가 있는 파일이 나타납니다. 파일별로 **거래 날짜 범위·거래가 있는 일수**와 파일 종류를 확인합니다. 이 시연 CSV는 4·5월 모두 거래일이 **26일**이며, 5월 마지막 거래일은 30일입니다. 휴무·무거래일이 있어도 전체 월을 내보낸 자료입니다.

**월 전체 여부 확인 필요**인 네 파일에서 **이 파일은 … 전체 내역이에요. (휴무·무거래일 포함)**을 각각 체크합니다. 4월은 **2021-04-01~30**, 5월은 **2021-05-01~31**로 저장됩니다. 이미 **월 전체 기간 확인됨**이면 다시 체크하지 않습니다. 후보가 여러 개면 사용할 파일을 고릅니다. 일부 날짜만 내보낸 자료는 전체 확인을 하지 말고 해당 월 전체 자료를 준비합니다.

확인이 끝나면 **보관한 POS 집계 완료**와 두 달 매출 미리보기, **상품 주문에서 10개 품목**이 표시되는지 확인합니다. 이후 새로고침해도 파일의 기간 확인은 유지됩니다.

**요즘 어떤 점이 고민인가요?**에는 아래 문장을 복사합니다.

> 4월보다 5월 매출이 줄었어요. 주변 한식 음식점 상권과 비교해 우리 가게 상황을 알고 싶어요.
> 어떤 메뉴와 시간대에서 매출이 많이 줄었는지 확인하고 싶어요.
> 그 근거를 바탕으로 6월에 무엇부터 바꾸면 좋을지 추천받고, 발주량과 홍보 방법도 정하고 싶어요.

메뉴 이름과 감소 수치를 미리 적지 않고 POS에서 근거를 찾게 합니다. **이 자료로 분석하기**를 누릅니다. 재시연은 분석 이름 끝에 회차를 붙여 구분합니다.

## 5. 매출·상권과 AI 근거 확인

매출 분석에서 다음 수치를 확인합니다.

| 확인할 지표 | 예상 표시 |
|---|---|
| 4월 → 5월 매출 | 32,379,500원 → 29,581,000원 |
| 우리 가게 매출 변화 | −8.64% |
| 같은 기간 애월 한식 카드 이용액 변화 | +7.34% |
| 오후 2~5시 결제 건수 | 337 → 189건 |
| 메뉴 매출 감소 사례 | 김치찌개 4,965,000원 → 4,221,000원 |

상권 비교의 금액·기간·제주데이터허브 출처를 펼쳐 확인합니다. 설명은 **“주변 한식 카드 소비는 늘었는데 우리 매출은 줄어, 우리 메뉴와 시간대의 변화를 더 살펴봅니다.”**로 연결합니다.

월별 매출 차트의 **이 차트 질문** 또는 짝꿍 질문창에서 다음 질문을 보냅니다.

> 매출이 가장 많이 줄어든 메뉴와 결제가 가장 많이 줄어든 시간대를 알려줘.

답변이 메뉴 매출과 오후 시간대 근거를 출처와 함께 보여주는지 확인합니다. 질문창의 **새 질문**으로 빈 대화를 다시 시작할 수 있습니다.

음성 시연은 **마이크 → 말하기 → 문장 수정 → 보내기** 순서입니다. 아이폰 Safari에서는 **중지** 후 변환된 문장을 확인합니다. 편집 중에는 전송되지 않고 보내기를 눌렀을 때 질문과 답변이 올라와야 합니다.

## 6. 사진과 메뉴 재료·원가 준비

**내 매장 → 메뉴 사진 관리**에서 고기국수 사진을 확인합니다. 이미 올린 사진은 그대로 사용합니다. 없는 경우 고기국수의 사진을 선택하고 **사진 저장**을 누릅니다. 새 메뉴를 추가할 때는 CSV와 같은 메뉴명을 사용합니다. [고기국수 예시 사진](../../frontend/src/assets/gogi-guksu.jpg)도 사용할 수 있습니다.

**내 매장 → 메뉴 재료·원가 → 메뉴 선택: 고기국수 → 재료 추가** 순서로 아래 값을 입력합니다. 기존 같은 재료 행이 있으면 그 행을 수정합니다.

| 입력 항목 | 시연 값 |
|---|---|
| 재료명 | 돼지고기 |
| 단위 | kg |
| 한 개당 사용량 | 0.5 |
| kg당 단가 (원) | 10600 |

**재료·원가 저장** 후 합산 원가 **5,300원**, POS 판매가 **8,500원**을 확인합니다. 이 값은 계산 확인용 설정이며 실제 식당 원가나 실제 조리법을 뜻하지 않습니다.

이번 발주·홍보는 오후 판매가 약해진 대표 메뉴 고기국수로 진행합니다. 고기국수는 월 전체 **495 → 505그릇**이고, 오후 2~5시 주문 시작 기준 **156 → 110그릇**입니다. 전체 매출이 가장 많이 줄어든 메뉴와 시연에서 발주·홍보할 메뉴를 구분해 설명합니다.

## 7. 제주데이터허브 근거를 반영한 대응 전략

저장한 분석의 **대응 전략 보기**로 돌아갑니다. 주문 안내 점검 전략의 **근거와 출처 보기**에서 우리 매출·시간대 변화와 제주데이터허브 근거를 확인합니다. AI 추천 문장은 달라질 수 있으므로 표현보다 수치·출처와 제안 행동의 연결을 확인합니다.

주문 안내 점검의 **선택하기 → 계획 시작일 2021-06-01 → 안내 수정 후 확인할 기간 2주 → 이 전략으로 계획 만들기**를 누릅니다. 안내 제안이 나오면 내용과 실제로 적용할 수 있는 조치를 확인합니다.

처음 이틀 준비 후 관찰 기간은 **2021-06-03~16**입니다. 실행 관리의 점검표를 펼쳐 준비·확인 순서를 보여줍니다. 실제로 수행하지 않은 일은 완료 처리하지 않습니다. 다음 전략은 같은 분석의 **대응 전략**으로 돌아가 선택합니다.

## 8. 고기국수 발주 검토

발주량 검토 전략의 **선택하기 → 계획 시작일 2021-06-01 → 실행 기간 2주 → 이 전략으로 계획 만들기**를 누릅니다.

실행 관리에서 **날씨를 확인할 날짜 2021-06-05 → 메뉴 고기국수 → 예상 판매량 보기**를 누릅니다.

| 확인·입력 항목 | 시연 값 |
|---|---|
| 예상 판매량 | 13~28그릇 |
| 날씨 비교 근거 | 제주 관측소, 강수 기록이 같았던 토요일 POS 6일 |
| 자동 불러온 사용량·원가 | 돼지고기 0.5kg/그릇 · 5,300원 |
| 현재 재고 입력 | 3kg |
| 입고 예정량 입력 | 1kg |
| 자동 계산된 예상 재료 사용량 | 6.5~14kg |
| 자동 계산된 추가 준비량 | 2.5~10kg |

재료명·단위·한 개당 사용량을 발주 화면에 다시 입력하지 않습니다. **발주 검토표 저장**을 누르면 예상 사용량 상한 **14kg**과 재고·입고를 기록합니다. **계산 근거 보기**에서 비교 날짜와 기상청 출처를 확인합니다. 예상 자체도 기록하려면 **예상 이력 관리 → 예상 범위 저장**을 누릅니다.

사용량 변경은 재고 입력을 먼저 저장한 뒤 **내 매장에서 사용량 수정 → 재료·원가 저장 → 저장한 사용량으로 발주 검토하기**로 진행합니다. 같은 계획·메뉴·조회 날짜로 돌아와 변경한 사용량으로 재계산합니다.

6월 5일 날씨는 실제 과거 관측 조건을 적용한 재현입니다. 6월 1일에 알 수 있었던 예보나 예측 성능 검증으로 설명하지 않습니다. 시연 기준일 이후의 실제 판매 결과는 대기 상태로 두며, 실행 후 매출 개선을 달성했다고 주장하지 않습니다.

## 9. 6월 전시와 연결한 세 채널 홍보

같은 분석의 홍보 전략을 선택해 시작일 **2021-06-01**, 실행 기간 **2주**, 홍보 채널 **인스타그램**으로 계획을 만듭니다. 실행 관리의 **프로모션 검토**에서 아래 조건을 확인하고 **프로모션 검토 저장**을 누릅니다.

| 입력·확인 항목 | 값 |
|---|---|
| 검토할 품목 | 고기국수 |
| 판매가 | 8,500원 |
| 저장된 원가 | 5,300원 |
| 개당 할인액 | 1,000원 |
| 할인 예산 | 30,000원 |
| 할인 후 판매가 | 7,500원 |
| 할인 가능한 최대 수량 | 30개 |
| 할인 기간 | 6월 1~14일 |

**홍보물 만들기**에서 게시 날짜 **2021-06-05**, 게시 시간 **11:00**, 행사 **제주현대미술관 《공(空)의 매혹》 전시**, 저장된 고기국수 사진을 선택합니다. 공개 후기 선택이 필요한 화면이면 확인한 소개 포인트를 선택하고 **선택한 포인트로 세 채널 초안 만들기**를 누릅니다. 후기 없는 기본 초안이 안내되는 경우 해당 버튼으로 진행하고 실제 후기 근거를 사용했다고 설명하지 않습니다. 기존 초안을 수정하는 화면에서는 **홍보 초안 변경 저장**을 누릅니다.

**홍보물 보기**에서 **인스타그램 → 네이버 플레이스 → 당근** 탭을 차례로 확인합니다. 전시 소식이 가게·고기국수 안내로 자연스럽게 이어지는지, 세 채널 모두 **7,500원·30개 한정·6월 1~14일**인지 확인합니다. 행사 출처도 열어 봅니다.

아이폰에서 같은 홍보 계획을 열어 탭 전환·스크롤 중 하단 버튼·**문구 복사**·**이미지 저장**을 확인합니다. 시연 중 실제 SNS 게시·예약은 하지 않습니다. 행사 없이도 만들 수 있음을 보여주려면 별도 초안에서 **행사 없이 만들기**를 선택합니다.

## 10. 아이폰에서 다국어 QR 메뉴판

**내 매장 → 다국어 QR 메뉴판 → 영어·중국어·일본어 초안 만들기**를 누릅니다. 메뉴별로 펼쳐 번역을 검토하고 고기국수 영어 이름을 **Jeju-Style Pork Noodle Soup**으로 확인합니다. AI 서비스를 호출할 수 없으면 아래 수동 번역 표를 사용합니다.

**세 언어의 메뉴명과 사진·가격을 확인했어요.**를 체크하고 처음에는 **메뉴판 공개**, 이미 공개한 메뉴판은 **변경 내용 공개**를 누릅니다.

PC의 관리 화면에 표시된 **현재 공개 QR**을 아이폰으로 스캔합니다. 로그인 없이 열리는지, 한국어·English·简体中文·日本語 전환과 고기국수 사진·**8,500원**이 보이는지 확인합니다. 이 가격은 정상 메뉴 가격이며 앞 단계의 할인 홍보 가격 7,500원과 구분합니다.

새 매장에 CSV 메뉴만 등록했다면 기준 메뉴는 **10개**입니다. 사진 관리에서 별도 이름으로 등록한 메뉴도 목록에 포함되므로 기존 매장을 재사용할 때는 메뉴명·사진·가격을 기준으로 공개 목록을 검토합니다. 번역을 수정해 다시 공개한 뒤 같은 QR 주소와 새로고침에서도 유지되는지 확인합니다.
