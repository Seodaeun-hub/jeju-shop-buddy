# 가게짝꿍 최종 촬영 순서 · PC + 아이폰

서비스: [gage-jjakkung.up.railway.app](https://gage-jjakkung.up.railway.app/). 촬영 자료 ZIP을 **먼저 압축 해제**하고 아래 번호 폴더를 순서대로 사용합니다. 계정 비밀번호·API 키는 영상과 문서에 표시하지 않습니다.

대상은 **더애월 본점 공개정보를 참고한 2021년 가상 운영 사례**입니다. 현재 매장 운영 성과나 식당의 참여를 입증하는 시연이 아닙니다. 개인 참가로 정리했으며 팀 전환 작업은 남은 항목에서 제외합니다.

## 촬영 전 준비

- PC는 가로 화면, 아이폰은 세로 화면으로 각각 녹화하고 편집에서 이어 붙입니다. 아래 8~10분은 권장 편집 분량이며 대회가 정한 영상 길이가 아닙니다.
- PC·아이폰에서 같은 새 HTTPS 주소로 로그인합니다. 이전 Railway 주소의 로그인 상태는 자동 이전되지 않습니다. 로그인 입력·권한 승인·알림 팝업은 본 촬영 전에 정리합니다.
- 첫 장면의 시연 기준일은 **2021-06-01**입니다. 현재 저장 상태가 6월 15일이라면 사이드바 **시연 기준일 → 날짜 변경 → 2021-06-01 적용**으로 돌립니다. 실행 결과를 보여줄 때만 6월 15일로 바꿉니다. PC 날짜는 바꾸지 않습니다.
- 기존 매장·분석·사진·계획을 삭제하지 않습니다. 이미 등록된 파일은 재사용합니다. 새로 업로드하는 장면이 꼭 필요하면 별도의 촬영용 매장/계정에서 진행하고, 기존 화면을 새 업로드 성공 장면처럼 편집하지 않습니다.
- 메뉴 사진 5장·재료·원가는 미리 입력해 둡니다. 영상에서는 김치찌개 한 항목을 펼쳐 **8,000원·재료 8개·원가 3,100원**만 설명하고 긴 입력 과정은 줄입니다.
- 한 번 끝까지 연습한 뒤 녹화합니다. AI·외부 검색 대기는 편집으로 줄일 수 있지만, 실패를 성공한 것처럼 연결하거나 다른 자료의 답변을 붙이지 않습니다.

첫 설명: “제주데이터허브의 실제 상권 자료와 더애월 공개정보를 바탕으로 가상 POS를 만들었습니다. 상권과 매장의 차이를 찾고 발주·홍보를 준비한 뒤 결과를 확인하는 과정을 보여드리겠습니다.”

## 1. 매장과 CSV 네 개

**내 매장 → 더애월 본점**을 선택합니다. 새로 등록할 때는 상호 **더애월 본점**, 주소 **제주특별자치도 제주시 애월읍 하가로 159**, 지역 **제주시 애월읍**, 업종 **한식 음식점업**입니다. 공개정보 참고·가상 운영임을 설명합니다.

촬영 폴더 **01_매출분석_처음넣는CSV**의 네 파일을 사용합니다.

| 순서 | 파일 | 화면에서 고를 종류 / 월 |
|---|---|---|
| 1 | SIMULATED-2021-04-payment.csv | 결제 내역 / 2021년 4월 |
| 2 | SIMULATED-2021-04-product.csv | 상품 주문 / 2021년 4월 |
| 3 | SIMULATED-2021-05-payment.csv | 결제 내역 / 2021년 5월 |
| 4 | SIMULATED-2021-05-product.csv | 상품 주문 / 2021년 5월 |

**POS 파일 관리 → 달력 보기 → 파일 추가**에서 저장하고, **매출 입력 → POS 파일 업로드 → 내 매장 월별 파일**에서 기준 월 2021-04 / 비교 월 2021-05를 고릅니다. 이미 보관했다면 재업로드하지 않고 선택합니다. 네 파일의 **월 전체 여부 확인**을 체크하고 집계 완료를 확인합니다. 월당 거래일은 26일이며 일요일 휴무는 시연 가정입니다.

분석 이름: **더애월 공개정보 참고 · 2021년 6월 가상 운영 시연**

‘요즘 어떤 점이 고민인가요?’:

> 4월보다 5월 매출이 줄었어요. 같은 애월 한식 상권과 비교해 우리 가게 상황을 알고 싶어요. 매출이 가장 많이 줄어든 메뉴와 결제가 줄어든 시간대를 찾아주세요. 그 근거로 6월 발주량을 검토하고, 실제 공개 후기에서 확인한 메뉴 특징을 살려 홍보하고 싶어요.

**이 자료로 분석하기**를 누릅니다. 이미 저장된 분석을 재사용하면 **매출 분석 → 저장된 분석**에서 같은 이름을 선택합니다.

## 2. 분석과 AI 질문

| 항목 | 확인값 |
|---|---|
| 월 매출 | 16,342,500원 → 14,508,000원, −11.23% |
| 같은 애월 한식 카드 이용액 | 2,049,456,994원 → 2,199,885,864원, +7.34% |
| 김치찌개 | 610→462인분 / 4,880,000→3,696,000원 |
| 오후 2~5시 결제 | 208→104건 |

**월별 매출 차트 질문** 또는 오른쪽 아래 **짝꿍 대화 열기**에서 “매출이 가장 많이 줄어든 메뉴와 결제가 줄어든 시간대를 근거와 함께 알려줘.”를 보냅니다. 메뉴명을 질문에 먼저 넣지 않습니다. **근거와 출처 보기**를 펼칩니다. AI 답변 문장은 바뀔 수 있으므로 숫자·기간·출처를 확인합니다.

말할 내용: “주변 같은 업종의 카드 이용액은 늘었지만 이 가상 매장 매출은 줄었습니다. 김치찌개와 오후 시간대를 먼저 점검할 근거가 나옵니다.” 메뉴와 시간대는 각각의 집계이며, 오후에 줄어든 주문이 모두 김치찌개였다고 단정하지 않습니다.

## 3. 사진·재료와 하루 발주

**04_메뉴사진_AI예시**의 번호와 이름이 같은 메뉴에 사진을 등록합니다. 식당의 실제 음식 사진이 아닙니다. 메뉴·가격·원가 입력은 **05_참고표_업로드금지**의 표를 봅니다. 참고표 CSV는 POS에 넣지 않습니다.

**대응 전략 보기 → 발주량 검토하기 → 선택하기 → 시작일 2021-06-01·2주 → 이 전략으로 계획 만들기**로 이동합니다. 기존 계획이 있으면 **실행 관리 → 해당 발주 계획 → 실행 관리 열기**로 재사용합니다.

1. 예상할 날짜 **2021-06-05**, 메뉴 **김치찌개** → **예상 판매량 보기**.
2. **20~24인분**, 최근 토요일 **30·32·28 → 22·24·20인분**과 계산 단계를 확인합니다. 강수 표본이 부족하면 날씨 보정은 생략되며, 이 범위에 날씨가 반영됐다고 설명하지 않습니다.
3. **예상 범위 저장**을 누릅니다. 결과 화면에서 예상이 안 보였던 문제를 피하려면 발주 검토표 저장과 별개로 이 버튼도 확인합니다.
4. 아래 표대로 현재 재고·기존 입고·최종 추가 발주량을 넣고 **발주 검토표 저장**을 누릅니다.

| 재료 / 단위 | 현재 재고 | 기존 입고 | 최종 추가 발주 예시 |
|---|---:|---:|---:|
| 돼지고기(원육) / kg | 1 | 0.5 | 1 |
| 김치 / kg | 2 | 1 | 1 |
| 두부 / kg | 1 | 0.5 | 0.5 |
| 양파 / kg | 0.5 | 0.2 | 0.1 |
| 완성 기본육수 / L | 4 | 2 | 2 |
| 쌀 / kg | 2 | 0 | 0.5 |
| 기본 반찬 / 인분 | 10 | 10 | 5 |
| 찌개 양념 / 인분 | 20 | 0 | 5 |

돼지고기 **2~2.4kg 사용 − 재고1kg − 기존입고0.5kg = 추가 준비0.5~0.9kg**을 보여줍니다. 이번 추가 주문을 기존 입고 칸에 중복 입력하지 않습니다. 실제 주문은 전송되지 않으며, 김치찌개에 배정한 재료 계산입니다.

## 4. 정상가 홍보·후기·세 채널

같은 분석에서 **대응 전략 → 대표 메뉴와 가게 소식 홍보하기 → 선택하기**를 누르고 시작일 **2021-06-01·2주**로 계획을 만듭니다. **시간대 한정 혜택 검토하기**와 혼동하지 않습니다. 이번 본편은 할인 없이 **정상가 8,000원**으로 통일합니다.

**홍보물 만들기 → 김치찌개 → 이 메뉴 후기 찾기**를 누릅니다. 기준일 이전 180일, **2021-02-14 공개 후기**의 날짜·원문을 확인하고 실제로 먹은 경험과 솥밥·누룽지 등 원문이 뒷받침하는 포인트만 고릅니다.

게시일 **2021-06-01**, 시간 **11:00**, 행사 **제주현대미술관 《공(空)의 매혹》** 전시를 고르고 사진을 선택해 **선택한 포인트로 세 채널 초안 만들기**를 누릅니다. **홍보물 보기**에서 인스타그램·네이버 플레이스·당근 문구와 출처를 확인합니다. 미확인 조리법·식감·혼밥 가능 여부·식당과 전시의 제휴나 거리를 주장하면 **초안 수정하기 → 홍보 초안 변경 저장**으로 고칩니다.

PC에서 계획 링크를 복사해 아이폰 Safari에서 같은 계획을 엽니다. 아이폰은 **홍보물 보기 → 세 채널 탭 → 스크롤 → 문구 복사 → 이미지 저장**을 촬영합니다. 과거 공개 후기와 오늘의 실시간 검색 성공 여부는 구분합니다. 재검색 실패 시 저장된 초안을 보여주면서 **사전 저장 초안 재생**이라고 표시합니다.

실제 Instagram 게시 장면은 선택입니다. 앱의 **인스타그램 열기** 이후 사용자가 시연 계정에서 직접 게시합니다. 맨 앞 문구는 “가게짝꿍 가상 시연 · 2021년 자료 재현 · 현재 실제 판매 행사 아님 · 음식 사진은 AI 예시”로 둡니다. 실제 게시일은 오늘이며 자동 게시·예약 기능이라고 설명하지 않습니다. 권한 없는 식당 채널에 게시하지 않습니다.

## 5. 실제 공개 QR과 아이폰

PC **내 매장 → 다국어 QR 메뉴판**에서 메뉴 5개·사진·정상가·번역을 확인합니다. 변경한 내용이 있으면 확인 체크 후 **변경 내용 공개**를 누릅니다. 다시 공개할 필요가 없다면 저장된 QR을 그대로 사용합니다.

아이폰 카메라로 **새 주소의 실제 공개 QR**을 찍고 한국어·English·简体中文·日本語를 전환합니다. 김치찌개 **8,000원**과 사진을 확인합니다. 촬영 폴더 **06_QR_현재공개메뉴판**의 QR은 묶음을 만든 시점의 공개 메뉴판에 연결됩니다. 메뉴판을 삭제·공개 중지했다면 PC에서 새 QR을 다시 받습니다. 홈 소개의 예시 QR을 실제 메뉴판 QR 대신 사용하지 않습니다.

2026-11-18에는 새 주소의 공개 API가 인증 없이 HTTP 200, 메뉴5·사진5와 네 언어 전환을 브라우저에서 확인했습니다. 내일의 실제 아이폰 스캔·녹화는 촬영자가 다시 확인합니다.

## 6. 6월 15일로 바꾸고 홍보 결과

여기서만 **시연 기준일 → 2021-06-15 적용**으로 바꿉니다. **실행 관리 → 대표 메뉴와 가게 소식 홍보하기 → 결과 확인**을 엽니다. 기간 종료는 삭제가 아닙니다.

자료 구분 **가상 시연 자료**, 실행 날짜 **2021-06-01**, 내용 **가상 홍보 초안 검토 및 오후 안내 실행**, 메모 **가상 운영 기록이며 실제 게시·성과 아님**을 적습니다.

**POS로 실행 전·후 비교하기 → 비교할 POS 메뉴명 → 김치찌개**를 고릅니다. **02_홍보결과_네칸순서** 안의 폴더 번호와 화면 입력칸을 맞춥니다.

| 실행 전 상품 주문 | 2_실행전_상품주문 | SIMULATED-2021-05-product.csv |
| 실행 후 결제 | 3_실행후_결제 | SIMULATED-2021-06-01-14-payment.csv |
| 실행 후 상품 주문 | 4_실행후_상품주문 | SIMULATED-2021-06-01-14-product.csv |

전 기간 **2021-05-18~31**, 후 기간 **2021-06-01~14**, 각 **12영업일**을 확인합니다. 5월 파일은 월 전체 파일이지만 여기서는 선택 기간만 집계합니다. 전체 영업 자료·요일·영업시간 확인란을 체크하고 **선택한 CSV로 집계하기 → 실행 기록과 결과 저장**을 누릅니다.

확인값: **김치찌개 204→247인분**, **오후 2~5시 48→72건**, 매출 **6,619,000→6,968,000원**. 실제 홍보 효과가 아니라 결과 확인 기능을 보여주는 가상 자료입니다.

## 7. 하루 발주 결과와 마무리

**실행 관리 → 발주량 검토하기 → 결과 확인**에서 자료 구분 **가상 시연 자료**, 실행 날짜·발주 검토한 하루 모두 **2021-06-05**, 메뉴 **김치찌개**를 고릅니다. 실행 내용 **가상 김치찌개 배정 재료 하루 점검**을 적습니다.

**03_발주결과_하루판매/업로드용**의 6월 상품 주문 CSV를 **하루 상품 주문 CSV로 판매량 채우기**에 넣습니다. **6월 5일 판매23인분 / 저장 예상20~24인분**을 확인합니다. ‘저장한 예상 자료 없음’이면 원래 같은 발주 계획에서 6/5 김치찌개의 **예상 범위 저장**을 먼저 하고 돌아와 새로고침합니다.

남은 재고는 **돼지고기0.2kg, 김치0.55kg, 두부0.16kg, 양파0.11kg, 육수1.1L, 쌀0.43kg, 반찬2인분, 양념2인분**을 입력합니다. 메모: “김치찌개 배정 재료 기준. 기존 예정량과 추가 발주 모두 당일 입고, 다른 메뉴 사용·폐기·이동 없음 가정.” **실행 기록과 결과 저장** 후 재조회합니다. `입력참고용` CSV는 이 값을 보는 표이며 파일 선택칸에 올리지 않습니다.

마지막은 **대응 한눈에 보기 → 흐름 재생**입니다. 실제 상권 → 가상 매장 감소 → 사장님 확인 → 발주·홍보 → 가상 결과를 연결합니다. 주문 안내·리뷰 실행 결과 입력은 본편에서 생략합니다.

마지막 설명: “AI가 근거를 정리하고 사장님이 수량과 홍보 문구를 확인합니다. 현재 영상의 실행 결과는 가상 자료이며 실제 매장 매출 개선이나 인과 효과를 검증한 것은 아닙니다.”
